# @atsms/dcgka

The ATSMS advanced-E2EE engine: a byte-faithful TypeScript port of **BeeKEM**
(Ink & Switch) plus the **ATSMS messaging profile** and the **ordering/auth**
layer. Implements [`spec/beekem-core.md`](../../spec/beekem-core.md),
[`spec/dgm.md`](../../spec/dgm.md), [`spec/ordering-auth.md`](../../spec/ordering-auth.md),
and [`spec/wire-format.md`](../../spec/wire-format.md). Decision **D11** /
Phases 1–2 of [`../../docs/history/implementation-plan.md`](../../docs/history/implementation-plan.md).

## Layout

| Module | Role |
|---|---|
| `src/keyhive.ts` | `keyhive_crypto` primitives (BLAKE3 `derive_key`, Siv, XChaCha20-Poly1305, X25519) — **byte-identical to the Rust oracle** (KDF split: BLAKE3 below the `PcsKey` seam) |
| `src/treemath.ts` · `tree.ts` · `keys.ts` · `secretstore.ts` · `encrypted.ts` | the BeeKEM ratchet tree (path encryption, resolutions, conflict-key merge/replay) |
| `src/kdf.ts` · `chains.ts` | profile layer above the seam: HKDF-SHA256 `atsms-beekem:v1:*` labels, per-sender FS-AEAD chains, `rootCommit` |
| `src/dgm.ts` | strong-remove DGM (SR1–SR5) as a pure validity filter |
| `src/engine.ts` | op graph + epochs + DGM-filtered merge/replay, PcsKey seam, coverage, eviction, checkpoints, head-reconciliation digest |
| `src/ordering.ts` · `frames.ts` | signed frames, signing-key rotation, readiness/buffering, welcome, repair, head advertisement |
| `src/cbor.ts` | strict deterministic CBOR (wire-format §1) |

## Test & build

```sh
npm ci
npm run typecheck      # tsc --noEmit
npm run test:unit      # everything except the fuzz gate (~1s)
npm run test:fuzz      # the simulation quality gate (~2min)
npm test               # all of it
```

CI (`.github/workflows/ci.yml`) runs typecheck + unit + fuzz on push/PR.

## Frozen test vectors (`../../test-vectors/`)

The normative byte-level regression gate (wire-format §9):

- `beekem-oracle.json` — seeded transcripts from the **Rust `beekem` crate**
  (differential oracle; `test/oracle.test.ts`). Regenerate via
  [`../../oracle/`](../../oracle) (needs the keyhive clone + rustc ≥ 1.90) —
  a deliberate, reviewed step, not run in CI.
- `kdf.json`, `frames.json` — generated by `test/vectors.test.ts` and frozen.
  To regenerate after a **deliberate** wire change: delete the file, re-run the
  test (it rewrites it), and review the diff.

A drift between the implementation's bytes and a frozen vector fails the test —
that is the point: wire changes must be intentional and reviewed.

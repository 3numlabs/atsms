# ATSMS P-256 Migration Guide

This document describes the changes made to the ATSMS library to:
1. Remove the root certificate authority system
2. Add P-256 ECDSA/ECDH support alongside RSA-2048
3. Make P-256 the default algorithm for new certificates

Use this guide to update server-side implementations and other ATSMS clients.

---

## Summary of Changes

| Component | Before | After |
|-----------|--------|-------|
| Certificate hierarchy | Root CA signs endpoint certs | Self-signed endpoint certs |
| Default algorithm | RSA-2048 | P-256 ECDSA |
| Signature (RSA) | RSA-SHA256 | RSA-SHA256 (unchanged) |
| Signature (P-256) | N/A | ECDSA with SHA-256 |
| Encryption (RSA) | RSA-OAEP (KeyTransRecipientInfo) | RSA-OAEP (unchanged) |
| Encryption (P-256) | N/A | ECDH-ES (KeyAgreeRecipientInfo) |
| JWT algorithm (RSA) | RS256 | RS256 (unchanged) |
| JWT algorithm (P-256) | N/A | ES256 |
| Content encryption | AES-256-CBC | AES-256-CBC (unchanged) |

---

## 1. Certificate Changes

### 1.1 Root Certificate Removed

The `ATSMSRootCertificate` class has been removed. Endpoint certificates are now **self-signed**.

**Before:**
```
Root Certificate (secp256k1)
    └── signs → Endpoint Certificate (RSA-2048)
```

**After:**
```
Endpoint Certificate (self-signed, RSA-2048 or P-256)
```

### 1.2 P-256 Endpoint Certificate

New certificate class `ATSMSP256EndpointCertificate` with:
- **Key type**: P-256 (secp256r1/prime256v1)
- **Signature algorithm**: ECDSA with SHA-256
- **Self-signed**: Certificate signs itself using its own private key
- **Key usage**: Same extensions as RSA (digitalSignature, keyEncipherment, TLS client/server)

### 1.3 Certificate Detection

Certificates can be detected by examining the public key algorithm:

```javascript
// Check certificate algorithm from X.509
function detectCertificateAlgorithm(certPEM) {
  // Parse certificate and check public key algorithm OID
  // RSA: 1.2.840.113549.1.1.1 (rsaEncryption)
  // EC:  1.2.840.10045.2.1 (ecPublicKey) with P-256 curve

  // Or check signature algorithm:
  // RSA: sha256WithRSAEncryption or RSA-PSS
  // EC:  ecdsa-with-SHA256
}
```

**OpenSSL verification:**
```bash
# Check algorithm
openssl x509 -in cert.pem -text -noout | grep -i "Public Key Algorithm"
# RSA: rsaEncryption
# P-256: id-ecPublicKey

openssl x509 -in cert.pem -text -noout | grep -i "Signature Algorithm"
# RSA: sha256WithRSAEncryption or rsassaPss
# P-256: ecdsa-with-SHA256
```

## 2. Encryption Changes

### 2.1 CMS/PKCS#7 Recipient Info Types

The encryption format depends on the **recipient's** certificate algorithm:

| Recipient Cert | CMS RecipientInfo Type | Key Encryption |
|----------------|------------------------|----------------|
| RSA | KeyTransRecipientInfo (variant 1) | RSA-OAEP with SHA-256 |
| P-256 | KeyAgreeRecipientInfo (variant 2) | ECDH-ES + AES-256 key wrap |

### 2.2 RSA Encryption (unchanged)

```
RecipientInfo ::= KeyTransRecipientInfo
  - keyEncryptionAlgorithm: RSA-OAEP (id-RSAES-OAEP)
  - oaepHashAlgorithm: SHA-256
  - encryptedKey: <AES key encrypted with RSA-OAEP>
```

### 2.3 P-256 ECDH Encryption (new)

```
RecipientInfo ::= KeyAgreeRecipientInfo
  - keyEncryptionAlgorithm: ECDH-ES (dhSinglePass-stdDH-sha256kdf-scheme)
  - ukm: <optional user keying material>
  - keyWrapAlgorithm: AES-256 key wrap (id-aes256-wrap)
  - recipientEncryptedKeys:
    - rid: IssuerAndSerialNumber or RecipientKeyIdentifier
    - encryptedKey: <AES key wrapped with derived key>
  - originatorKey: <ephemeral EC public key>
```

**Key derivation for ECDH:**
1. Generate ephemeral P-256 key pair
2. Perform ECDH with recipient's public key → shared secret
3. Use HKDF-SHA256 to derive AES-256 key wrap key
4. Wrap content encryption key with AES key wrap
5. Include ephemeral public key in `originatorKey`

### 2.4 Content Encryption (unchanged)

Both RSA and P-256 use the same content encryption:
- Algorithm: AES-256-CBC
- IV: Random 16 bytes per message
- Padding: PKCS#7

### 2.5 Decryption

Decryption must handle both recipient info types:

```javascript
async function decrypt(envelopedData, recipientCert, recipientPrivateKey) {
  // Find matching RecipientInfo by certificate serial/issuer
  const recipientInfo = findRecipientInfo(envelopedData, recipientCert);

  if (recipientInfo instanceof KeyTransRecipientInfo) {
    // RSA-OAEP decryption
    const cek = rsaOaepDecrypt(recipientInfo.encryptedKey, recipientPrivateKey);
    return aesDecrypt(envelopedData.encryptedContent, cek);
  }
  else if (recipientInfo instanceof KeyAgreeRecipientInfo) {
    // ECDH decryption
    const ephemeralPubKey = recipientInfo.originatorKey;
    const sharedSecret = ecdh(recipientPrivateKey, ephemeralPubKey);
    const kek = hkdfSha256(sharedSecret);
    const cek = aesKeyUnwrap(recipientInfo.encryptedKey, kek);
    return aesDecrypt(envelopedData.encryptedContent, cek);
  }
}
```

## 3. Signature Changes

### 3.1 PKCS#7 SignedData

The signature algorithm depends on the **sender's** certificate:

| Sender Cert | Signature Algorithm | OID |
|-------------|---------------------|-----|
| RSA | RSA-SHA256 | 1.2.840.113549.1.1.11 |
| P-256 | ECDSA-SHA256 | 1.2.840.10045.4.3.2 |

### 3.2 Signature Verification

```javascript
async function verifySignature(signedData) {
  const signerCert = extractSignerCertificate(signedData);
  const signature = signedData.signerInfos[0].signature;
  const signedAttrs = signedData.signerInfos[0].signedAttrs;

  const algorithm = detectCertificateAlgorithm(signerCert);

  if (algorithm === 'RSA') {
    return rsaSha256Verify(signerCert.publicKey, signedAttrs, signature);
  } else if (algorithm === 'P256') {
    return ecdsaSha256Verify(signerCert.publicKey, signedAttrs, signature);
  }
}
```

## 4. JWT Authentication Changes

### 4.1 Algorithm Selection

JWT algorithm is determined by the **private key type**:

| Key Type | JWT Algorithm | Signature |
|----------|---------------|-----------|
| RSA | RS256 | RSASSA-PKCS1-v1_5 with SHA-256 |
| P-256 EC | ES256 | ECDSA with P-256 and SHA-256 |

### 4.2 Key Type Detection

Detect key type from PKCS#8 PEM by checking the AlgorithmIdentifier OID:

```javascript
function detectKeyType(privateKeyPEM) {
  // Decode PEM to DER
  const der = base64Decode(stripPemHeaders(privateKeyPEM));

  // Check for EC OID: 1.2.840.10045.2.1
  // Hex: 06 07 2A 86 48 CE 3D 02 01
  if (derContains(der, '06072a8648ce3d0201')) {
    return 'EC';
  }

  // Check for RSA OID: 1.2.840.113549.1.1.1
  // Hex: 06 09 2A 86 48 86 F7 0D 01 01 01
  if (derContains(der, '06092a864886f70d010101')) {
    return 'RSA';
  }

  return 'RSA'; // Default fallback
}
```

### 4.3 JWT Structure (unchanged)

```json
{
  "header": {
    "alg": "ES256",  // or "RS256" for RSA
    "typ": "JWT",
    "kid": "<certificate-serial-number>"
  },
  "payload": {
    "sub": "at://<did>/at.atsms.x509/<cert-serial>",
    "iss": "<did>",
    "aud": "atsms-api",
    "iat": 1706000000,
    "exp": 1706003600
  }
}
```

### 4.4 Server-Side JWT Verification

```javascript
async function verifyJWT(token) {
  const { header, payload } = decodeJWT(token);

  // Fetch certificate from PDS
  const cert = await fetchCertFromPDS(payload.iss, header.kid);
  const publicKey = extractPublicKey(cert);
  const algorithm = detectCertificateAlgorithm(cert);

  // Verify algorithm matches
  if (algorithm === 'P256' && header.alg !== 'ES256') {
    throw new Error('Algorithm mismatch: P-256 cert requires ES256');
  }
  if (algorithm === 'RSA' && header.alg !== 'RS256') {
    throw new Error('Algorithm mismatch: RSA cert requires RS256');
  }

  // Verify signature
  return jwtVerify(token, publicKey, { algorithms: [header.alg] });
}
```

## 5. Mixed Algorithm Support

The system supports mixed RSA/P-256 environments:

| Sender | Receiver | Signature | Encryption |
|--------|----------|-----------|------------|
| RSA | RSA | RSA-SHA256 | RSA-OAEP |
| P-256 | P-256 | ECDSA-SHA256 | ECDH-ES |
| RSA | P-256 | RSA-SHA256 | ECDH-ES |
| P-256 | RSA | ECDSA-SHA256 | RSA-OAEP |

**Key insight**: Signature algorithm depends on sender; encryption depends on recipient.

- [ ] Update decryption to handle both RecipientInfo types

---

## 8. Security Considerations

1. **Key strength**: P-256 provides ~128-bit security (comparable to RSA-3072)
2. **Forward secrecy**: ECDH-ES uses ephemeral keys, providing forward secrecy for encryption
3. **Algorithm agility**: Both algorithms remain supported indefinitely for backward compatibility
4. **No algorithm downgrade**: Signature/encryption algorithm is determined by certificate type, not negotiated
